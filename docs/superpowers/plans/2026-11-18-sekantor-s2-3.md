# SeKantor S2.3 (subagents, compact layout) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** (1) Claude Code subagents appear as junior avatars beside their main agent and report to it
when they finish; the main agent reports to you. (2) The office looks good with few agents: rooms sized
to their members, balanced rows, the lobby fully visible, plates close to their avatars.

**Facts (docs/spike/payloads/claude-desktop/06_SubagentStop.json, docs/spike/claude-hooks.md):** Claude
Code sends `SubagentStart` / `SubagentStop` with `session_id` (the parent's), `agent_id`, `agent_type`,
and on stop `last_assistant_message`; tool hooks fired inside a subagent carry `agent_id` too. Today
translate.py ignores them and the installer does not register Subagent* events.

## Global Constraints
- Hooks stay async, exec form, fail silently; never auto-approve; local only.
- A subagent never changes the parent's status, activity or summary.
- Tests never touch port 7878, Task Scheduler or the real home; no push. Only the FINAL test/build run
  must pass. Commits end with the worker's Co-Authored-By trailer. ADR-0028 for the subagent model.

## Shared contract
Session JSON gains `subagents: [{ id: string, type: string, status: "working" | "reported", activity:
{tool, kind} | null, summary: string | null, started_at: string, ended_at: string | null }]` (working
first, then reported; reported ones are kept 60 s after `ended_at`, then dropped).

---

### Task 1: Subagent tracking (hub + hook installer, Python)
- install.py: register `SubagentStart` and `SubagentStop` (async, exec form like the others);
  `Installed.current_shape()` is False when they are missing (so `doctor` says reinstall).
- translate.py: SubagentStart → event `subagent_started` (agent_id, agent_type); SubagentStop →
  `subagent_ended` (agent_id, summary from last_assistant_message); a PreToolUse with `agent_id` →
  `subagent_activity` (activity tool/kind) — none of these change the parent's status/activity/summary.
  Schema: optional `subagent: {id, type?}` on Event plus the new event types (ADR-0028).
- status.py / store / api: maintain `subagents` per session per the contract; prune reported ones 60 s
  after they end (no timers: prune on read/next event); `session_json` exposes them.
- Tests: translation of all three; parent untouched; lifecycle; pruning; old installs flagged.
- Commit `feat: track Claude Code subagents`.

### Task 2: Compact layout + subagent visuals (web)
- Layout: room interior sized to its members (desks for main agents + junior desks for their working
  subagents), no oversized empty floor; with ≤ 3 rooms place them in one row; otherwise balanced rows
  with the last row centred (no big empty cell); lobby at the front centre and fully visible (no cut
  wall/exit strip); keep "whole office fits the screen" and refit on layout signature changes; plates
  sit just above their avatar's head.
- Subagents: a smaller "junior" avatar (same look family as its main agent, smaller sprite or a
  lanyard/badge cue) at a junior desk next to the main agent's desk, animated by its own activity; when
  it becomes `reported` it walks to the main agent's desk holding a paper, pauses, then leaves through
  the room door; the main agent shows a brief "receiving" pose. Card for a main agent lists its
  subagents (type, status, summary).
- Tests: few-room layouts (1, 2, 3 rooms) have no empty grid cell and fit; lobby inside bounds;
  subagent desk beside its main agent; reported subagent routes to the main desk then the door.
- Commit `feat(web): compact rooms and junior subagents`.
