# SeKantor S2.1 (reports, art pass) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** (1) An agent that finished its turn without asking for anything is a *report*, not
"needs you": it brings a report to your desk and you accept it. (2) A richer, still original,
procedural pixel-art office.

**Owner decisions (2026-11-18):** report status as proposed; a plain-text question at the end of a
turn stays a report (no "?" heuristic); art option C (art pass on our own sprites; a commissioned kit
comes before the public release).

**Spec:** `docs/superpowers/specs/2026-11-16-sekantor-design.md` 6.1-6.2 (this plan amends 6.2: "done,
waiting for a new task" → report at your desk until accepted, then pantry).

## Global Constraints

- Needs you = only `waiting_approval`, a `waiting_input` that carries a real question/input request
  (`request.kind` in {"question"} or a Notification of type `agent_needs_input`, `elicitation_dialog`,
  `elicitation_url_dialog`), and `error`. A finished turn is not needs you.
- No answer controls: "Accept" only marks a report as read in SeKantor; nothing is sent to the agent.
- Public event schema change → ADR-0027.
- Art: original, not resembling any existing game; procedural (code-drawn) only; ≤ 12 fps and the
  idle rules from S2 still hold.
- Tests never touch port 7878, Task Scheduler or the real home. No push without the owner's approval.
- Python: `uv run pytest -q` (own worktree venv); web: `cd web && npm test && npm run build`.

### Task 1: Report status (hub + web)

**Interfaces:**
- `schema.Status` gains `reported` (between `running` and `done` in inbox order).
- Claude Code: `Stop` → `reported` (summary = last assistant message, `request: {"kind": "report"}`);
  `Notification` `idle_prompt` → keeps the session `reported` (no change); `agent_needs_input` /
  elicitation → `waiting_input` as today. tmux idle prompt → `reported`. OpenBot: pending prompt/approval
  → as today (needs you); idle → `done`.
- Hub: `NEEDS_YOU` excludes `reported`; `POST /v1/sessions/{id}/acknowledge` (cookie or bearer, Origin
  checks as other POSTs) stores `acknowledged_at` on the session; `session_json` adds
  `report_pending: bool` (= status `reported` and not acknowledged since `status_since`). Notifications:
  no toast for `reported`.
- Web: `Pose` gains `"report"` (avatar at your desk holding a paper) when `report_pending`; accepted
  reports → pantry/coffee. Header: "N busy · N need you · N reports · N errors". AvatarCard: "Accept"
  button when `report_pending`. Mini view: needs-you avatars as now plus a reports count.
- ADR-0027.
- [ ] Failing tests first (translate, status engine order + needs_you, acknowledge endpoint, session_json,
  notify, web model pose/counts/card); implement; commit `feat: report status for finished turns`.

### Task 2: Art pass (web sprites only)

- Bigger, richer sprites: 32x32 tiles and 32x48 characters (a `TILE` constant in sprites/render, model
  stays in tile units; scaling math in OfficeView follows `TILE`), soft drop shadows, textured wood floor
  and wallpaper with skirting, windows with daylight, wall lamps, bookshelves, rugs, plants in pots,
  desk details (monitor glow, mug, papers), office chairs, a proper server rack with blinking LEDs, a
  coffee corner, a door with a frame. Characters: head/hair/torso/legs shading, 4-frame walk, typing,
  reading, coffee, "!" balloon, smoke puff, and a new "report" pose (holding a sheet of paper).
- Optional day/night tint from the local clock (cheap: one overlay per frame, no extra timers).
- Keep the `Theme` interface (so a kit can replace it) and the S2 performance rules (static layer cache,
  sprite cache, 12 fps).
- [ ] Update sprite tests (grid sizes, palette-only); renderer tests still pass; commit
  `feat(web): art pass for the office`.
