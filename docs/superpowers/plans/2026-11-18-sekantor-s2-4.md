# SeKantor S2.4 (floors, Orca teams) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** (1) One floor per source app (Claude, Orca, OpenBot), switched with buttons; each floor fills
the screen and has its own lobby with your desk. (2) On the Orca floor a room is an Orca *project*;
the agent in the project's main worktree is the lead (validator) and agents in its other worktrees are
juniors that report to the lead; the lead reports to you. (3) Orca workers that are not Claude (Codex,
Gemini) appear too, with a model badge.

**Owner decisions (2026-11-18):** floor buttons; Claude Code in a terminal / VS Code / Claude desktop is
floor 1 "Claude"; your desk on every floor; room name = the Orca project name; main worktree = lead.

**Facts (docs/spike/orca-workers.md):** Orca agents inherit `ORCA_AGENT_SESSION_ID` (and workers
`ORCA_TERMINAL_HANDLE = structworker_<uuid>`). `orca orchestration dispatch-show --task <id> --json
--full` gives `assignee_orca_session_id` and `creator_orca_session_id` (the coordinator's
`ORCA_AGENT_SESSION_ID`). `orca orchestration worker-list --json --full --limit 100` lists workers with
`projection.provider.{id,model}`, `projection.stage.activity`, `projection.liveness`, outcome.
`orca worktree ps --json --limit 100` gives `worktrees[].{repo, path, agents[].{paneKey, agentType,
state}}` where `paneKey = structured-agent-session-<orca-session-id>:<pane>`; `repo` is the Orca project
display name (e.g. `D:\Ronda` shows as `SeKantor`). CLI calls take 1–4 s each.

## Global Constraints
- Watch only, never auto-approve, local only; hooks stay async exec form.
- Orca CLI calls happen only in the opt-in Orca pos (never in the hub or a hook), read-only commands
  only, with timeouts, backoff and last-good data; no mailbox bodies, no prompt/reply previews leave the
  pos.
- A junior never changes its lead's status/activity/summary.
- Tests never touch port 7878, Task Scheduler, the real home or the real `orca` CLI (inject a fake
  runner); no push. Only the FINAL test/build run must pass. Commits end with the worker's
  Co-Authored-By trailer.

## Shared contract (session JSON, hub → web)
```ts
floor: "claude" | "orca" | "openbot"      // openbot: source/host openbot; orca: host app orca or source orca; else claude
team: {
  project: string;        // Orca project name (pos), else the git main-repo folder name (see Task 1)
  worktree: string;       // worktree folder name; equals project folder for the main checkout
  role: "lead" | "junior";
  lead: string | null;    // session id of this junior's lead (null for leads / unknown)
  model: string | null;   // e.g. "gpt-6.2-sol", "gemini-3.8-flash"; null for Claude hook sessions
} | null                  // null outside the Orca floor
report_to: "you" | "lead" // reported junior with a known lead → "lead" (and report_pending false)
```
`agent` already names the agent (`claude`, `codex`, `gemini`/`antigravity`, …). On the Orca floor the
web groups rooms by `team.project` (fallback `project.name`).

## Pos → hub contract (Orca pos events, `POST /v1/events`, source `orca`)
- **Placement** for every live Orca agent seen in `worktree ps`: event type `orca_placement`,
  `session_id = "orca-agent:<orca_session_id>"`, `orca: {session_id, project, worktree, main: bool,
  creator: <creator orca session id> | null, model: str | null}`. The hub stores it in a table keyed by
  orca session id (expires 2 min after last seen) and does NOT create a session for it; any session whose
  hook env carried the same `ORCA_AGENT_SESSION_ID` takes that team info.
- **Non-Claude workers** (provider/agentType not claude) become their own sessions:
  `session_id = "orca:<orca_session_id>"` (one avatar per Orca agent, with status from its newest
  dispatch), `agent` = provider id, normal `status_changed`/`activity`
  events (running while stage is working, `reported` on outcome succeeded/settled or `worker_done`,
  `error` on failed, `session_ended` when the dispatch disappears or liveness is dead for 60 s) plus the
  same `orca` block on each event.

### Task 1: Floors and teams (hub, Python)
- hosts.yaml / hook env whitelist: add `ORCA_AGENT_SESSION_ID` and `ORCA_TERMINAL_HANDLE` (both the
  Python hook and `hook-env.txt` for the native hook come from the same list); store them on the session.
- Schema: optional `orca` block on Event and the `orca_placement` type (ADR-0029: floors and Orca teams).
- `session_json`: `floor`, `team`, `report_to` per the contract.
  - Team without the pos: for an Orca-floor session, git checkout of its cwd: `.git` is a directory →
    main checkout (role lead, project = folder name); `.git` is a file `gitdir: <repo>/.git/worktrees/<n>`
    → linked worktree (role junior, project = `<repo>` folder name, worktree = cwd folder name). Cheap,
    cached with the project detection cache.
  - With a placement: project/worktree/main/model from it.
  - Lead: the session whose orca session id equals the junior's `creator`; else the most recently
    active lead session in the same project on the Orca floor; else null.
- Report routing: a junior with a lead that becomes `reported` has `report_to: "lead"`,
  `report_pending` false (it never asks you to Accept); approvals/questions/errors of juniors still need
  you exactly as today.
- Tests: floor per host/source; git main vs linked worktree; placement overrides; lead by creator and by
  project fallback; junior report never pending; whitelist includes the two names (native + Python).
- Commit `feat(hub): floors and Orca teams`.
