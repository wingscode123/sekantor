# SeKantor S1.5 (fewer flagged executables) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** SentinelOne flags every run of the unsigned PyInstaller `sekantor-hook.exe` (it runs on every
agent action) and `sekantor.exe` ("Suspicious file executed", reputation-based). Make the hook a tiny
native forwarder, stop launching `sekantor.exe` on every app start, and make the RAM pin opt-in.
Code signing comes later (owner decision, 2026-11-17).

**Architecture:** The hook becomes a ~300 KB Rust binary that reads the hook payload from stdin and
POSTs it, with a whitelisted set of env vars and its own event id, to a new hub endpoint
`POST /v1/hooks/claude`. The hub does what the Python hook did (ignore_cwd, translate, fingerprint,
the deep host follow-up). The desktop app reads first-run state from a new `GET /v1/setup` instead of
running `sekantor.exe setup --json`. The Python hook stays for source installs.

**Tech Stack:** Python 3.11 hub (FastAPI), Rust stable (std only + a small HTTP-over-TcpStream, no
async), Tauri 2 app, CircleCI Windows job.

**Spec:** `docs/superpowers/specs/2026-11-16-sekantor-design.md` (section 8 "Hooks": "may become a small
native forwarder that posts the raw payload and the hub does the translating").

## Global Constraints

- The hook never blocks or changes an agent: always exit 0, never write stdout/stderr, hard limit
  2.0 s total (watchdog), HTTP timeout 1.0 s (1.5 s for `SessionEnd`), stdin capped at 4 MiB.
- Hub on 127.0.0.1 only; bearer token from `<home>/token` on every request; no outbound network.
- Event semantics unchanged: same translation, same `event_id` format (16 hex of time_ns + 8 random
  hex), `sent.log`/`hook.log` line formats unchanged so `sekantor stats` keeps working.
- The hook does not send the whole environment: only names listed in `<home>/hook-env.txt` (written
  by the hub) plus `CLAUDE_PID`.
- Tests never touch real services, the real home or port 7878 (conftest guard).
- No Rust toolchain on the owner's machine: Rust compiles and its tests run on CircleCI only.
- Conventional Commits; Python suite green before each commit; commit messages end with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. ADR for the forwarder (ADR-0026).

## Review Focus

1. Hub down / slow (owner's laptop pages): the forwarder exits 0 within ~1-2 s, logs one
   "hub unreachable (<Err>) <id>" line, never hangs. (Task 2: cargo test against a listening socket that never answers.)
2. Non-UTF-8 or huge stdin, non-object JSON: forwarder exits 0 silently (Task 2 tests); hub returns 4xx
   for a malformed body without crashing (Task 1 tests).
3. `ignore_cwd` (OpenBot helper runs) still drops events — now in the hub. (Task 1 test.)
4. A secret in the environment (e.g. `ANTHROPIC_API_KEY`) is never sent: only whitelisted names.
   (Task 2 test.)
5. Old Python hooks keep working against the new hub (both paths coexist). (Task 1: existing hook tests stay green.)

### Task 1: Hub endpoints (Python)

**Files:** `src/sekantor/hub/api.py`, `src/sekantor/hub/app.py`, `src/sekantor/pos/claude_code/hook.py`
(move the build logic into a function the hub can call; keep the Python hook working),
`src/sekantor/config.py` (`keep_in_ram`), `src/sekantor/cli.py` (`up` honours it; `setup` report
function reused), tests in `tests/test_hub.py`, `tests/test_hook.py`, `tests/test_config.py`.

**Interfaces (produces):**
- `POST /v1/hooks/claude` (bearer only, like `/v1/login-code`), body
  `{"v": 1, "id": "<event id>", "ts": "<ISO 8601 UTC>", "payload": {<hook stdin object>}, "env": {"NAME": "value", ...}}`.
  The hub: drops it when `settings.ignored(payload.cwd)` (202 `{"stored": false}`); otherwise builds the
  event exactly as the Python hook's `build_event` (translate + process pid from `env.CLAUDE_PID` +
  env-only fingerprint), using the body's `id` and `ts`; stores it like `POST /v1/events`; for
  `session_started` schedules the deep host follow-up off the request path (thread). 202
  `{"stored": true, "event_id": id}`. 422 for a malformed body; payload > 4 MiB → 413.
- On start the hub writes `<home>/hook-env.txt`: one env var name per line = every `env:` name in the
  loaded host rules plus `CLAUDE_PID`, sorted, unique.
- `GET /v1/setup` (bearer only): the same JSON `sekantor setup --json` prints (reuse the function).
- Setting `keep_in_ram` (config.toml): default `true` when running from source, `false` when frozen;
  `up` calls `resident.keep_resident()` only when it is true.

- [ ] Failing tests: endpoint stores the same event the Python hook would build for a PreToolUse
  payload (compare against `hook.build_event` on the same input); ignore_cwd → not stored; cookie → 403;
  malformed → 422; SessionStart triggers the follow-up (monkeypatch the deep collector); `hook-env.txt`
  contents; `/v1/setup` matches `setup --json`; `keep_in_ram` default by frozen flag.
- [ ] Implement; full suite green; commit `feat(hub): accept raw Claude Code hook payloads and report setup over the API`.

### Task 2: Native hook forwarder (Rust, `hook/`)

**Files:** `hook/Cargo.toml` (package `sekantor-hook`, edition 2021, no dependencies except
`serde_json` 1.x; `[profile.release] opt-level = "z", lto = true, strip = true, panic = "abort"`),
`hook/src/main.rs` (thin), `hook/src/lib.rs` (logic + tests), `docs/adr/0026-native-hook.md`.

**Interfaces:**
- Consumes Task 1's endpoint and `hook-env.txt`.
- Behaviour: start a watchdog thread that calls `std::process::exit(0)` after 2.0 s; read stdin up to
  4 MiB (more → exit 0); parse JSON; not an object → exit 0; home = `SEKANTOR_HOME` or
  `%USERPROFILE%`/`$HOME` + `.sekantor`; token = trimmed `<home>/token` (missing → log
  "no token: run `sekantor up` once", exit 0); port = `SEKANTOR_URL` port or `SEKANTOR_PORT` or 7878;
  env = names from `<home>/hook-env.txt` present in the environment (case-insensitive on Windows) plus
  `CLAUDE_PID`; id = `{time_ns:016x}{4 random bytes hex}` (random from `/dev/urandom` or
  `std::collections::hash_map::RandomState`-seeded, no crate); append `sent.log` line
  `<ts> <id> claude:<session_id> <hook_event_name>` (rotate to `.1` past 2 MiB); POST over a plain
  `TcpStream` to 127.0.0.1:port with HTTP/1.1, `Connection: close`, read/write/connect timeouts 1.0 s
  (1.5 s when `hook_event_name == "SessionEnd"`); non-2xx or error → append `hook.log` line
  `<%Y-%m-%dT%H:%M:%S local> <hook_event_name>: hub unreachable (<ErrKind>) <id>` (rotate past 256 KiB).
  Always exit 0, never print.
- [ ] cargo tests: env whitelist (secret not sent, case-insensitive match on Windows); id format; request
  bytes (method, path, headers, JSON body shape); a listener that never answers → returns within ~1.1 s
  with an error; refused port → error; non-object JSON and oversize stdin → no request; sent.log line format.
- [ ] Commit `feat(hook): native forwarder for Claude Code hooks` (compiles on CI in Task 4).
