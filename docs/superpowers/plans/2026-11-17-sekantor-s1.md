# SeKantor S1 (desktop shell, Windows installer built on CircleCI) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A double-click Windows installer (unsigned, built on CircleCI) that installs SeKantor as a
desktop app: a window and tray icon on top of the existing hub, which keeps running in the background.

**Architecture:** The Python hub is frozen with PyInstaller (onedir) into three executables that share
one folder: `sekantor.exe` (console CLI), `sekantor-hub.exe` (windowed, runs `up`), `sekantor-hook.exe`
(console, the Claude Code hook). A Tauri v2 app (`desktop/`) bundles that folder as a resource, makes
sure a hub runs, and shows the hub's web UI in its window through a one-time login code. First run
offers "Connect Claude Code". The NSIS installer and the Tauri build run only on a CircleCI Windows
executor; nothing Rust-related is installed on the owner's laptop.

**Tech Stack:** Python 3.11, PyInstaller 6, Tauri 2 (Rust stable, NSIS bundle), Node 20, CircleCI
`circleci/windows` orb.

**Spec:** `docs/superpowers/specs/2026-11-16-sekantor-design.md` (sections 5.3, 6.4, 8 "Setup", 9 S1).

## Global Constraints

- The hub binds to 127.0.0.1 only and needs the token on every request; the app reads the token from
  `~/.sekantor/token` and never stores it elsewhere. No outbound network calls from hub or app.
- Hooks fail silently and never block an agent; the frozen hook keeps exec form, async except SessionEnd.
- The hub outlives the window: closing the window hides it; only "Quit SeKantor" in the tray stops the hub.
- Unsigned Windows installer only (macOS/Linux and signing come before the public release).
- Nothing may install Rust, MSVC or PyInstaller on the owner's machine; `pyinstaller` lives in a
  `packaging` dependency group that only CI syncs. Never run `uv sync`/`uv add` in `D:\Ronda` (the
  owner's hub runs from its `.venv`); in a worktree, `uv sync` makes that worktree's own `.venv`.
- Tests never touch real services or the real home (the `tests/conftest.py` guard stays; new tests
  that run service or install commands monkeypatch them).
- Conventional Commits, small; full Python suite green before each commit (`uv run pytest -q`).
  Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- ADR for each non-trivial decision; code, comments, commits, docs in English.

## Review Focus

1. The app starts while no hub runs (first install, or after "Quit"): it starts one and the window
   still loads instead of showing an error. (Task 4: `ensure_hub` unit test with a fake launcher.)
2. The hub is busy for several seconds (the owner's laptop pages heavily): health checks and the login
   code request must retry, not fail the window on the first timeout. (Task 4: retry test.)
3. The installer runs on a machine with an existing source install (owner): first run must not install
   a second set of hooks or a second service; it replaces them with the frozen paths. (Task 3: setup
   test with existing `sekantor-hook` handlers pointing at a venv path.)
4. A path with spaces (`C:\Users\First Last\AppData\Local\SeKantor\...`) for the frozen executables in
   hooks and in the service task. (Tasks 1 and 3: tests with a spaced path.)
5. Uninstalling the app leaves no hooks and no service behind. (Task 5: NSIS pre-uninstall hook runs
   `sekantor.exe uninstall claude --global` and `sekantor.exe service uninstall`; checked in the CI smoke step.)

  `src/sekantor/service.py` (`hub_command`)
- Test: `tests/test_selfexe.py`, `tests/test_service.py`

**Interfaces:**
- Produces:
  - `selfexe.frozen() -> bool` (`getattr(sys, "frozen", False)`).
  - `selfexe.self_command(*args: str) -> list[str]`: frozen → `[str(Path(sys.executable).with_name(CLI_EXE)), *args]`
    where `CLI_EXE = "sekantor.exe"` on win32 else `"sekantor"`; not frozen → `[sys.executable, "-m", "sekantor.cli", *args]`.
  - `selfexe.hub_exe() -> list[str]`: frozen → `[str(... with_name("sekantor-hub.exe" | "sekantor-hub"))]`;
    not frozen → today's `pythonw -m sekantor.cli` prefix (moved from `service.hub_command`).
  - `service.hub_command(home)` = `selfexe.hub_exe() + ["up", "--no-open", "--log-file", <home>/hub.log]`.

### Task 4: Tauri shell (`desktop/`)

**Files:**
- Create: `desktop/package.json` (`@tauri-apps/cli` 2.x as devDependency; scripts `tauri`),
  `desktop/src-tauri/{Cargo.toml,tauri.conf.json,build.rs,src/main.rs,src/hub.rs,src/setup.rs,capabilities/default.json,icons/}`,
  `desktop/ui/index.html` + `desktop/ui/setup.js` (a plain first-run page: status list and a
  "Connect Claude Code" button; no framework), `docs/adr/0024-desktop-shell.md`
- Icons: generate from `brand/` with `tauri icon` in CI or commit generated PNG/ICO files.

**Interfaces:**
- Consumes: `sekantor setup --json|--apply` (Task 3), `POST /v1/shutdown` (Task 2), existing
  `GET /v1/health` and `POST /v1/login-code` (bearer).
- Produces (Rust, `hub.rs`, unit-tested with `cargo test`):
  - `fn home_dir() -> PathBuf` (`SEKANTOR_HOME` or `~/.sekantor`), `fn read_token(home) -> Option<String>`,
    `fn hub_port() -> u16` (`SEKANTOR_PORT` or 7878).
  - `fn ensure_hub(launch: impl Fn() -> io::Result<()>, health: impl Fn() -> bool, sleep: impl Fn(Duration)) -> Result<(), String>`:
    if `health()` is false, call `launch()` once, then poll `health()` every 500 ms for up to 30 s.
  - `fn login_url(port, code) -> String` = `http://127.0.0.1:{port}/?login={code}`.
  - HTTP to the hub with `ureq` (or `std::net` + minimal HTTP), 5 s timeout, 3 tries with 1 s pause.
- Behaviour:
  - Single instance (`tauri-plugin-single-instance`): a second launch shows the existing window.
  - On start: resources dir has `sekantor/` (the PyInstaller folder). Run `sekantor.exe setup --json`
    (hidden window, `CREATE_NO_WINDOW`); if `hooks != "ok"` or `service == false`, show `ui/index.html`
    (first-run page). Its button invokes the Tauri command `connect()` which runs `setup --apply` and
    then continues. Otherwise go straight on.
  - Then `ensure_hub` (launch = spawn `sekantor-hub.exe up --no-open --log-file <home>/hub.log`,
    detached, no window), get a login code, and navigate the main window to `login_url`.
  - Window close → hide. Tray menu: "Open SeKantor", "Quit SeKantor" (POST `/v1/shutdown`, then exit).
  - `tauri.conf.json`: identifier `dev.sekantor.app`, productName `SeKantor`, bundle target `nsis`,
    `resources: {"../../dist/sekantor/": "sekantor/"}`, CSP allows only `http://127.0.0.1:*` and self.
- [ ] **Step 1: Write `cargo test` unit tests** for `ensure_hub` (healthy → no launch; unhealthy then
  healthy after 3 polls → one launch; never healthy → Err after the timeout using a fake clock/sleep),
  `read_token` (trims newline; missing file → None), `login_url`, and the retry helper (2 failures then success).
- [ ] **Step 2: Implement** the shell. It cannot be built locally (no Rust on this machine): it is
  built and tested by Task 5's CI job. Keep `main.rs` thin; logic lives in `hub.rs`/`setup.rs` so the
  tests cover it.
- [ ] **Step 3: Commit** — `feat(desktop): Tauri shell with tray, first run and hub attach`

- Test: `packaging/smoke.py` runs in CI.

**Interfaces:**
- Consumes: Tasks 1-4.
- CI job `desktop-windows` (orb `circleci/windows@5`, executor `win/default`):
  1. checkout; install uv (pip), Node 20 (nvm or choco), Rust stable (rustup-init `-y --profile minimal`);
     cache `~/.cargo`, `desktop/src-tauri/target`, npm and uv caches keyed on lockfiles.
  2. `cd web && npm ci && npm run build`.
  3. `uv sync --group packaging` then `uv run pyinstaller packaging/sekantor.spec --distpath dist`.
  4. `uv run python packaging/smoke.py dist/sekantor` with `SEKANTOR_HOME` set to a temp dir:
     `sekantor.exe version` exits 0; `sekantor-hook.exe` with a PreToolUse payload on stdin and no hub
     exits 0 in under 5 s with empty stdout; `sekantor-hub.exe up --no-open --port 7899` then
     `GET /v1/health` with the token from the temp home → 200 within 30 s; `sekantor.exe stop` → hub gone.
  5. `cd desktop/src-tauri && cargo test`.
  6. `cd desktop && npm ci && npx tauri build` → `store_artifacts` of
     `desktop/src-tauri/target/release/bundle/nsis/*.exe`.
  - Runs on `main` and on branches matching `/^desktop-.*/`, plus when the pipeline parameter
    `desktop: true` is set (manual trigger). The Linux `python` and `web` jobs keep running on every push.
